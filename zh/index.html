areel 的由来
areel /əˈriːl/

不是什么巧妙的缩写。AREEL 是一张专辑——ariiol 的十二首曲子，这个域名就取自它的名字。

我很喜欢这张唱片。它属于那种每听一遍都会冒出新细节的作品，名字在脑子里留了很久，久到想把它挂在门头上。这页的水泥灰、那道洋红弧线和黑白棋盘格，全都取自它的封面。

这些功劳全归 ariiol。名字是这个页面上最好的东西，而且原本就不属于我——既然读到这里了，不妨给这张专辑留出半小时，它比这个网站精彩得多。

HydrogenH₁

自托管 LLM 代理。核心巧思是 Micro Agents——把多阶段编排藏进单个模型名，客户端一行代码不用改。

已上线 TypeScript MIT 自托管

核心特性 — Micro Agents

一个模型名进来。
多轮模型调用出去。

Micro Agent 把一整条工作流塞进一次普通模型调用里。客户端只管按名字请求，拿回一条正常回答；中间经历了几个阶段，对客户端完全透明。

比如先让视觉模型把图片转写成文字，再交给纯文本模型回答。这只是最直观的用法——每个阶段做什么完全由你定义，上限只取决于想象力。

一次调用的内部流向

客户端发出 一个模型名 + 一张图片
单次请求进入
阶段 1 — 读图 视觉模型将图片转写成文字
文本就地替换图片
阶段 2 — 作答 纯文本模型直接生成回答
返回单条结果
客户端收到 一条再普通不过的响应
实际用法
01

回复前先复核一遍

几个模型一起把问题想清楚。

一个模型起草，第二个模型挑刺，不通过就回炉重写。每个回答背后不止一个脑子，而客户端只看到最终定稿。

draft · 强模型起草 critique · 另一个强模型评审 评审回复 “APPROVED” → 直接返回初稿 → 结束 否则继续向下 ↓ revise · 强模型修订 → 结束

只需多花一次调用。第二个模型可以看到你的工具定义，但不会替你实际触发调用。

02

按难度付钱

让便宜模型决定什么时候请贵的。

阶段 1 只跑最便宜的模型给问题分级。由它的判断决定分流——难题交给旗舰模型，简单问题落回小模型直接回答。

triage · 便宜模型分级 输出包含 “HARD” → 转交强模型 → 结束 否则继续向下 ↓ answer · 便宜模型作答 → 结束

分级只耗一次廉价调用；如果改用正则分流，router 阶段甚至零开销。

FishBall鱼丸

安卓上的联网问答助手。核心规矩是绝不硬猜——每句结论都能追到已分级的发布机构，查不到就直说。

已上线 Kotlin MIT Android

核心特性 — 经得起核对的出处

每个答案都写明
话是从哪儿来的。

答案还没动笔，每条查到的资料先按发布者分级——监管部门、正规机构、实名个人，还是匿名帖子。级别直接标在答案下面，也决定措辞语气：单靠论坛帖子撑着的说法，绝不会用引述卫生部门的口吻来说。

如果查不到高于最低一级的资料，它会直接告诉你没查到。没有出处的回答跟好回答长得一模一样，只是少了一条反正没人去核对的引用。

一个问题的内部过程

查证中…
  • 已搜索 — 抓回 9 条结果
  • 正在阅读国家药监局说明书
  • 已为每条来源的发布机构分级
  • 正在反方向搜索相反说法
  • 逐字核对每条引文与原网页

会，最常见的副作用在胃肠道，国家药监局的药品说明书将恶心与胃烧灼感列在首位。

实际机制
01

引文是切出来的，不是生成的

模型指位置，校验器切原文。

展示来源原话时，模型从不自己敲字。它只标出位置，由代码从抓回的网页原文里原样截取并逐字核对，对不上直接打回重选。在代码里，编出来的引文没有任何一条路能走到屏幕上。

select · 模型标出原文区间 verify · 从抓回的网页原样切片 逐字吻合 → 展示引文 → 结束 否则打回 ↓ retry · 告知原因重新挑选 → 结束

模型老实引用时不产生额外开销——大多数时候正是如此。

02

先试图推翻自己

第二轮搜索专门找反方证据。

遇到要紧的问题，它会专门搜一轮跟第一轮结论唱反调的资料。两边对不上就如实并列呈现。照单全收第一页看到的说法，正是自信错答的起点。

support · 按原问题查证 disconfirm · 搜索相反主张 两边一致 → 直接给出结论 → 结束 否则继续向下 ↓ show both · 明确列出分歧 → 结束

多花一轮检索时间，这也是健康类问题需要二十到四十秒的原因。

DSH-FishballV3

DeepSeek Harness (DSH) 上的常驻个人助手会话。通过标准 MCP + OAuth 2.1 统筹其它 DSH 会话，汇总进度、处理审批并分派任务，自身不直接改写本地文件。

V3 Alpha DSH 4 个仓库 MCP · OAuth 2.1 MIT

核心架构 — 一个总管会话，一条公开接口

一个会话统筹全局。
其余会话专注干活。

Fishball 在 DSH 里维护一条长期在线的个人助手会话。它从其它工作会话和插件汇集进展，整理任务清单，在授权范围内代为处理权限审批、提问与方案评审，并把具体任务派给对应会话——自己始终不直接动本地工作区文件。

两端代码彼此零依赖：被管理侧通过 dsh-connector 暴露标准 MCP 接口，Fishball 像普通 MCP 客户端一样接入。既可一条命令装好内嵌整合版，也能独立部署、跨机互联，或让其它 MCP Agent 直接接入。

$ dsh plugin --profile web add dsh-fishball-bundle@1.0.0-alpha.1

四个仓库如何协作

统一入口 · 一键内嵌整合包 dsh-fishball-bundle
一条命令打包两端与子实例桥接
被管 DSH 侧 · MCP + OAuth 2.1 dsh-connector (connector · adapter · watchdog)
/api/agent/mcp — 唯一公开接口
托管桥接 · 隔离运行子 DSH dsh-fishball-instance (dsh-instance)
拉起子进程并同步模型与凭证
助手侧 · 核心运行时与组件 dsh-fishball (core · board · heartbeat · taskboard)
四个仓库一览
01 · 推荐入口

dsh-fishball-bundle

面向普通用户的主入口仓库。提供一键内嵌整合包（内置 instance、connector、adapter 与 watchdog），同时包含独立部署与外部 MCP 接入指南。

npm · dsh-fishball-bundle
02 · 被管侧连接器

dsh-connector

通用的 DSH MCP + OAuth 2.1 连接器插件，提供会话移交/收回（Hand over / Take back）、侧栏入口 UI、跨 DSH 适配器与按目标自动审权的 Watchdog。

npm · dsh-agent-connector · dsh-connector-amenities
03 · 助手运行时

dsh-fishball

Fishball 侧插件集，把一个 DSH 变成单会话总管助手——内置人设、私有 Skills、配对界面，以及工作看板、空闲缓存心跳与任务面板等可选组件。

npm · fishball-core · fishball-amenities
04 · 子实例托管桥

dsh-fishball-instance

在主 DSH 内托管运行隔离的 Fishball 子实例（<DSH_HOME>/fishball/runtime），自动同步 API-Key 模型配置、签发连接令牌并提供完整清理脚本。

npm · dsh-instance
